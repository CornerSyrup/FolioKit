# Records, experience and resume

Each round ends with a progress record stating actual tool outputs and their paths, independent panels successfully generated, composite outputs, failed attempts, review status, missing evidence and next ready tasks. Planned panels do not count as generated. A pending final tool call remains unknown until a result is observed.

Resume state records workshop ID, framework version, source registry, decisions, active baseline/layout versions, selected attempt IDs, unfinished tasks, blockers, tool limits and the next useful batch. This makes progress portable without relying on another conversation's inaccessible state.

Lessons record: goal; observed result; evidence; failure mode; proposed rule; verification method; applicability; confidence; subsequent experiments. Distinguish session observations from general limitations. “Several independent requests returned composites” does not establish that a tool can never render an independent image.

Cross-workshop lessons omit identity values and unavailable source details. Keep a decision log and change log. Do not overwrite a past decision or silently reinterpret a user's original annotation.
