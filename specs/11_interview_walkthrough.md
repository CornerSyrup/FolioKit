# Interview walkthrough — interaction test plan

This is a hypothetical conversation pattern, not a character preset or an executed test.

## Start without prepared fields

User: “I want to make a reference kit for a new character.”

Host: “What will you use the kit for, and do you already have references or want to establish the design together?”

The host creates discovery records itself. It does not hand the user JSON or require a panel inventory.

## Sources arrive gradually

User supplies one source now and mentions more later.

The curator registers the available source only; the host records the others as unavailable if relevant. Work can continue on available evidence. The host asks which features the supplied reference should govern if this is unclear; it does not assume the entire image is authoritative.

## Consequential ambiguity

User says a surface should be “translucent”, while the reference appears opaque.

The host states the conflict and asks whether the text instruction or pictured material should govern. It records the answer and updates the baseline. It may organise files and plan unrelated sections while waiting, but does not generate dependent production panels using an unrecorded guess.

## Different characters and source counts

To test independence, begin a separate workshop with a non-human character and another with a human character. Supply different reference counts and omit an atlas in one run. No role should request a particular previous hairstyle, outfit, eight-view series or fixed number of source sheets. Ask only applicable feature questions.

## Interview acceptance checks

- Ordinary language is enough to begin; no placeholder filling is required.
- Already answered questions are not repeated.
- Questions are small batches connected to the next decision.
- The host writes and updates all structured records.
- Routine reversible choices do not cause repeated approval requests.
- Unavailable evidence stays unavailable; interview answers cannot fabricate file contents.
- Missing answers block only dependent work, and resume notes preserve the state.

These scenarios are proposed usability checks. No end-to-end workshop trial is claimed in this draft.
