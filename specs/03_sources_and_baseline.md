# Sources and character baseline

No default character exists. Do not presume human anatomy, a particular presentation, age, hairstyle, skin, clothes or art style. Interview according to applicability; mark irrelevant features not_applicable.

Sources have stable IDs, type, locator, availability, hash where bytes are available, designated authority domains, annotations and constraints. Accept any number. Unavailable files may be registered, but observations cannot be invented. Sources mentioned in user prose are not automatically available or authorised file references.

Annotations use top-left origin and normalised coordinates [0,1]; record source dimensions and point or bounding box. Record whether an annotation governs geometry, emotional intent, camera, material or another feature. Do not use coordinates without source association. Resolving a coordinate is different from knowing why the user selected it.

Baseline feature entries include ID, applicable domain, value, status (decided/proposed/unknown/not_applicable), evidence references, invariant/variant/flexible classification, acceptance description, and criticality. Example domains, not mandatory defaults: silhouette, proportions, surfaces, palette, facial structure, hair/fur texture, makeup, marks, garment construction, layers, coverage, material opacity, accessories and asymmetry.

Establish visually useful baseline references before dependent generation. Textual colour descriptions may be supplemented by approved visual swatches; never invent sampled values. Lighting and display affect perceived colour; compare under declared conditions. Numerical tolerances require an explicit method and rationale, not arbitrary precision.

Left/right means character-relative unless a panel explicitly declares another coordinate system. Camera yaw convention and visible side must be defined in the workshop plan. Do not copy front-view asymmetry to rear image coordinates blindly.

A frozen baseline is versioned and supported by decisions, not necessarily a separate approval ceremony. Source priority is per domain. All subsequent changes carry affected-feature IDs and invalidate relevant panel reviews until rechecked. Cross-character reusable lessons must omit character values.
